# 05 — Data Model v2 (additive to `data-model.md`)

> Rules: **additive migrations only** (new tables, new nullable columns, new enum values in their own migration files). Do not drop or rename existing columns; deprecate instead. Money stays integer minor units; times `timestamptz`; IDs UUID unless the auth library requires text IDs (then use its generated ids and keep FKs as `text`).

## 1. What changes at a glance

| Existing | Change |
|---|---|
| `users` | Becomes the Better Auth **user** table (add `email_verified`, `image`, `banned`, `ban_reason`, `ban_expires`, platform `role` for staff `user|support|admin`, `timezone`, `last_sign_in_at`). `users.role` (buyer/seller) and `persona_key` are **deprecated** (stop reading). `is_agent` deprecated (agents become service accounts) |
| `contracts` | Add `buyer_org_id`, `seller_org_id`, `created_by_user_id`, `template_id`, `current_version`, `seller_invite_email`; keep `buyer_id/seller_id` (deprecated, nullable going forward) |
| `api_keys` | Add `org_id`, `service_account_id`, `scopes text[]`, `expires_at`; keep hash/prefix columns |
| `jobs` enum | Add `SEND_EMAIL`, `EXPIRE_INVITES`, `NOTIFY_DEADLINES` (separate migration) |
| `ledger_events` | Unchanged. `actor_type` gains value `service_account` (CHECK change via new constraint, additive) |

## 2. Migration sequence

| File | Contents |
|---|---|
| `0004_better_auth.sql` | Better Auth tables generated by its CLI, reconciled with Drizzle naming: `users` (existing, extended), `session` (+ `active_organization_id`, `impersonated_by`), `account`, `verification`, `organization`, `member`, `invitation`, `two_factor`; indexes |
| `0005_orgs_contract_ownership.sql` | `org_settings`, `paypal_connections`; new columns on `contracts`; indexes on `buyer_org_id`, `seller_org_id`; backfill script run separately |
| `0006_collaboration.sql` | `counterparties`, `contract_versions`, `contract_invitations`, `contract_comments`, `funding_approvals`, `templates` |
| `0007_notifications_email.sql` | `notifications`, `notification_preferences`, `email_outbox`, `consent_records`, `support_tickets` |
| `0008_audit_service_accounts.sql` | `audit_events` (+ append-only trigger), `service_accounts`, columns on `api_keys` |
| `0009_job_types.sql` | `ALTER TYPE job_type ADD VALUE IF NOT EXISTS 'SEND_EMAIL'; ...` (**each value in its own statement; file contains nothing else**) |
| R2 later | `webhook_endpoints`, `webhook_deliveries`, `attachments`, `disputes_internal`, `feature_flags`, `receipts` |

`scripts/backfill-orgs.ts` (idempotent): create **Demo Workspace** org; add all seeded demo users as members (buyer→member/owner as appropriate); set `contracts.buyer_org_id/seller_org_id` from users' demo org; set `created_by_user_id = buyer_id`.

## 3. Tables

### 3.1 Better Auth tables (names follow the library's generated schema; shown for reference)
```
users(id, email unique, email_verified bool, name, image, banned bool, ban_reason, ban_expires,
      role text default 'user' /* user|support|admin (platform) */, timezone text default 'UTC',
      last_sign_in_at, created_at, updated_at)
session(id, user_id, token unique, expires_at, ip_address, user_agent, active_organization_id, impersonated_by, created_at, updated_at)
account(id, user_id, provider_id, account_id, password hash nullable, access_token..., created_at)
verification(id, identifier, value, expires_at, created_at)
organization(id, name, slug unique, logo, metadata, created_at)
member(id, organization_id, user_id, role text /* owner|admin|finance|member|viewer */, created_at, unique(organization_id,user_id))
invitation(id, organization_id, email, role, status, expires_at, inviter_id, created_at)
two_factor(id, user_id, secret enc, backup_codes enc)
```

Custom roles `finance` and `viewer` are defined in the access-control config (`02` §5).

### 3.2 `org_settings`
```sql
CREATE TABLE org_settings (
  organization_id text PRIMARY KEY REFERENCES organization(id) ON DELETE CASCADE,
  funding_approval_threshold_minor int CHECK (funding_approval_threshold_minor IS NULL OR funding_approval_threshold_minor >= 0),
  members_can_accept_contracts boolean NOT NULL DEFAULT false,
  default_auto_release_hours int NOT NULL DEFAULT 48 CHECK (default_auto_release_hours BETWEEN 1 AND 168),
  require_mfa_roles text[] NOT NULL DEFAULT '{}',          -- R2 enforcement
  intent text NOT NULL DEFAULT 'both' CHECK (intent IN ('seller','buyer','both')),
  onboarding_completed_at timestamptz,
  checklist_dismissed_at timestamptz,
  updated_at timestamptz NOT NULL DEFAULT now()
);
```

### 3.3 `paypal_connections`
```sql
CREATE TABLE paypal_connections (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  organization_id text NOT NULL REFERENCES organization(id) ON DELETE CASCADE,
  mode text NOT NULL DEFAULT 'PLATFORM_ACCOUNT' CHECK (mode IN ('PLATFORM_ACCOUNT','PARTNER_CONNECTED')),
  status text NOT NULL DEFAULT 'NOT_CONNECTED' CHECK (status IN ('NOT_CONNECTED','PENDING','ACTIVE','RESTRICTED','REVOKED')),
  paypal_merchant_id text,            -- seller merchant id in PayPal (R2)
  paypal_email text,
  tracking_id text UNIQUE,            -- our id passed to partner referrals (R2)
  onboarding_url text,
  permissions_granted boolean,
  last_checked_at timestamptz,
  connected_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (organization_id)
);
```
R1: one row per org with `mode='PLATFORM_ACCOUNT'`, `status='ACTIVE'` (sandbox merchant); UI explains. R2 switches seller orgs to `PARTNER_CONNECTED` and the release service passes the seller's `paypal_merchant_id` and auth-assertion to PayPal (see `paypal-integration.md` update note in `07`).

### 3.4 Contract ownership changes
```sql
ALTER TABLE contracts
  ADD COLUMN buyer_org_id text REFERENCES organization(id),
  ADD COLUMN seller_org_id text REFERENCES organization(id),
  ADD COLUMN created_by_user_id uuid REFERENCES users(id),
  ADD COLUMN template_id uuid,
  ADD COLUMN current_version int NOT NULL DEFAULT 1,
  ADD COLUMN seller_invite_email text;
CREATE INDEX contracts_buyer_org_idx ON contracts(buyer_org_id, created_at DESC);
CREATE INDEX contracts_seller_org_idx ON contracts(seller_org_id, created_at DESC);
```
Invariant: after `PROPOSED`, `buyer_org_id` is set; after `ACCEPTED`, both org ids are set and **different** (an org cannot contract with itself; `CHECK (buyer_org_id IS NULL OR seller_org_id IS NULL OR buyer_org_id <> seller_org_id)`).

### 3.6 `contract_versions`
```sql
CREATE TABLE contract_versions (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  contract_id uuid NOT NULL REFERENCES contracts(id) ON DELETE CASCADE,
  version int NOT NULL, contract_json jsonb NOT NULL, contract_hash text NOT NULL,
  change_note text, created_by uuid REFERENCES users(id), created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (contract_id, version)
);
```
A version is created on each **send** (PROPOSED). `contracts.contract_json` always equals the latest version until ACCEPTED, then it is frozen and `contract_hash` equals that version's hash.

### 3.7 `contract_invitations`

```sql
CREATE TABLE contract_invitations (

  side text NOT NULL CHECK (side IN ('seller','buyer')),
  email text NOT NULL,
  token_hash text NOT NULL UNIQUE,                      -- sha256 of the emailed token

  accepted_by uuid REFERENCES users(id),

CREATE UNIQUE INDEX contract_invitations_one_pending ON contract_invitations(contract_id, side) WHERE status = 'PENDING';
```

### 3.7b `funding_approvals` (R1)
```sql
CREATE TABLE funding_approvals (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  contract_id uuid NOT NULL REFERENCES contracts(id) ON DELETE CASCADE,
  organization_id text NOT NULL REFERENCES organization(id),
  requested_by uuid NOT NULL REFERENCES users(id),
  total_minor int NOT NULL,
  status text NOT NULL DEFAULT 'PENDING' CHECK (status IN ('PENDING','APPROVED','REJECTED','CANCELLED','EXPIRED')),
  decided_by uuid REFERENCES users(id), decision_note text,
  created_at timestamptz NOT NULL DEFAULT now(), decided_at timestamptz,
  CHECK (decided_by IS NULL OR decided_by <> requested_by)       -- four-eyes
);
CREATE UNIQUE INDEX funding_approvals_one_pending ON funding_approvals(contract_id) WHERE status = 'PENDING';
```
`startFunding` requires: no threshold, or `total < threshold`, or an `APPROVED` row for the same `total_minor`.

## 4. Query patterns and indexes (hot paths)

| Query | Index |
|---|---|
| Contracts for my active org (either side), newest first | `contracts_buyer_org_idx`, `contracts_seller_org_idx` (UNION or `WHERE buyer_org_id = $1 OR seller_org_id = $1`) |
| Inbox items (needs attention) | computed from milestones/approvals/invitations by org; no table; cached 5 s |
| Notifications unread count | `notifications_user_idx` |
| Pending contract invitation by token | `contract_invitations.token_hash` unique |
| Audit log by org | `audit_org_idx` |
| Members of org | Better Auth `member(organization_id)` |

## 5. Validation and invariants

1. Every org-scoped row carries `organization_id`; every query for org data **filters by the active org from the session**, never from request input alone.
2. A contract's two orgs differ; seller org is set at acceptance; buyer org at creation.
3. `funding_approvals.decided_by ≠ requested_by`; approvals expire after 7 days.
4. Service account key scopes ⊆ service account scopes; forbidden scopes can never be stored (CHECK via `NOT (scopes && ARRAY['escalation:decide','release:retry','payment:refund'])`).
5. Emails and notifications are created in the **same transaction** as the state change that triggers them (outbox pattern); delivery is asynchronous.
6. `audit_events` and `ledger_events` are append-only.
