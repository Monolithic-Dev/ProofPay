# ProofPay — Project Structure

## 1. Repo layout decision

**Single repository, single `package.json`** (not a workspace monorepo). Three runnable entry points share code:

| Process | Entry | Command (dev) | Command (prod) |
|---|---|---|---|
| Web (UI + API) | `next` | `npm run dev` | `npm run start` |
| Worker | `src/worker/index.ts` | `npm run worker` | `npm run worker:start` |
| MCP server | `src/mcp/server.ts` | `npm run mcp` | `npm run mcp:start` |

Why: 10 days, 4 people; a workspace adds config overhead with no benefit. Shared code lives in `src/server/` and `src/shared/`.

## 3. Naming conventions

| Thing | Convention | Example |
|---|---|---|
| Files | kebab-case | `required-keywords.ts` |
| React components | PascalCase, one per file | `FundsBar.tsx` |
| DB tables / columns | snake_case, plural tables | `ledger_events.prev_hash` |
| Money | integer minor units, suffix `_minor` | `amount_minor` |
| Timestamps | `timestamptz`, suffix `_at` | `auth_created_at` |
| IDs | UUID v4 (`gen_random_uuid()`); milestone/criterion **keys** are short strings inside a contract (`m1`, `c1`) | `milestones.milestone_key = 'm1'` |
| Enums | UPPER_SNAKE in DB/TS | `RELEASE_FAILED` |
| Endpoints | plural nouns, `/api/v1` prefix, kebab-case verbs only for actions | `POST /contracts/{id}/fund` |
| Ledger event types | UPPER_SNAKE past tense | `CAPTURE_COMPLETED` |
| Job types | UPPER_SNAKE imperative | `RELEASE_MILESTONE` |
| Prompts | `name.vN.ts` + exported `PROMPT_VERSION` | `rubric.v1.ts` |
| Env vars | UPPER_SNAKE, grouped prefix | `PAYPAL_CLIENT_ID` |
| Idempotency keys (PayPal) | `pp:{contractId}:{milestoneKey}:{action}:{n}` | `pp:9c1…:m1:capture:1` |

## 4. Where do I start? (day-one orientation)

1. `cp .env.example .env`, fill `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET` (sandbox), `ANTHROPIC_API_KEY`, `SESSION_SECRET` (`openssl rand -hex 32`).
2. `docker compose up -d` (Postgres), `npm i`, `npm run db:migrate`, `npm run seed`.
3. **Run the spike first:** `npx tsx scripts/paypal-spike.ts`. It must create an `AUTHORIZE` order, pause for you to approve it as the sandbox buyer, authorize, capture $60 (non-final), capture $40 (`final_capture: true`), and also test void and the reauthorize call shape. **Do not build further until this passes** (see `roadmap.md`, M0 gate: Nov 3, 12:00 IST).
4. Read, in order: `prd.md` → `architecture.md` → `data-model.md` → `paypal-integration.md` → `ai-pipeline.md`.
5. First code to write: `src/server/contracts/schema.ts` (Zod `Contract`), `src/server/verify/policy.ts` (pure, fully unit-tested), `src/server/ledger/append.ts`. Everything else depends on these three.
6. Run `npm run dev`, `npm run worker`, and (when needed) `npm run mcp` in three terminals. Use a tunnel (`cloudflared tunnel --url http://localhost:3000` or ngrok) to receive PayPal webhooks locally and register that URL in the PayPal dashboard.

```

db:generate, db:migrate, seed,

eval, chaos, lint, typecheck, spike:paypal
```
