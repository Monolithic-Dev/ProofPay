# ProofPay — *Pay when it's proven.*

**ProofPay holds a PayPal payment and releases it milestone by milestone, only when AI-assisted, evidence-backed checks confirm the work meets criteria both sides agreed to up front. It works for humans and for AI agents.**

> ⚠️ **Honesty box:** ProofPay uses a **PayPal authorization hold**, not legal escrow. It never holds funds. **PayPal sandbox only**: no real money. PayPal's terms, the 29-day authorization window, and possible fees apply.

## The problem

Paying for work you can't inspect in advance (data, writing, research, or work done by an AI agent) forces one side to trust the other. Freelancers Union reports about 71% of freelancers have had non-payment issues; buyers pay upfront for work whose "done" was never defined; and as AI agents start hiring other agents, nobody is there to check the result. Existing agent-payment protocols settle payments; **none verifies delivery.**

## What ProofPay does

1. **Compile:** describe a job in English → a contract with **measurable acceptance criteria**; a **linter** flags vague criteria ("high quality") and offers one-click fixes.
2. **Hold:** the buyer approves a **PayPal authorization** for the total. The seller sees the funds are real; the buyer isn't charged yet. *The authorization is the budget cap.*
3. **Verify:** each milestone passes **deterministic checks first**, then an **AI rubric verifier that must quote verbatim evidence** (quotes are substring-verified by code), plus an **adversarial pass** that flags prompt-injection attempts.
4. **Decide (in code):** a pure **policy engine** returns PASS / REJECT / ESCALATE. **The AI never controls money.**
5. **Release:** PASS → **PayPal partial capture** for that milestone (the last uses `final_capture`). Failed work gets exact feedback; repeated failure **voids** the remaining hold. Declines and outages are handled and reconciled.
6. **Prove:** every step is a **hash-chained ledger** event; export a **Proof Pack** (JSON/PDF) usable as dispute evidence.

> **AI proposes, code decides, PayPal moves the money.**

## How PayPal is used (sandbox)

| Capability | Where |
|---|---|
| Orders v2 with `intent: AUTHORIZE`, buyer approval, authorize | Funding |
| Payments v2 **multiple partial captures** + `final_capture` | One capture per verified milestone |
| **Void** remaining authorization | Final failure / cancel |
| **Reauthorize** across the 3-day honor period (worker) | Long-running contracts (implemented; tested with mocks) |
| **Refund** (partial/full) `[S]` | Post-capture corrections |
| **Webhooks** with signature verification, idempotent handling | State confirmation, reconciliation |
| `PayPal-Request-Id` idempotency; `PayPal-Mock-Response` negative testing | Safe retries; **12-case chaos suite** |
| Disputes **provide-evidence** `[C]` | Proof Pack as seller evidence (if built; see `docs/`) |

## Run locally

```bash
git clone <REPO_URL> && cd proofpay
cp .env.example .env                 # fill PAYPAL_CLIENT_ID/SECRET (sandbox), ANTHROPIC_API_KEY, SESSION_SECRET
docker compose up -d                 # Postgres 16
npm install
npm run db:migrate && npm run seed
npx tsx scripts/paypal-spike.ts      # optional: proves your sandbox account can authorize + partially capture
npm run dev                          # terminal 1: web  → http://localhost:3000
npm run worker                       # terminal 2: worker (verification, release, reauth, reconcile)
npm run mcp                          # terminal 3 (optional): MCP server
```
For webhooks locally, expose port 3000 with a tunnel (`cloudflared tunnel --url http://localhost:3000`) and register `<tunnel>/api/v1/webhooks/paypal` in the PayPal developer dashboard (`PAYPAL_WEBHOOK_ID`).
Useful: `npm run test`, `npm run eval`, `npm run chaos`, `npm run lint`, `npm run typecheck`.

## Limitations (stated plainly)

- Sandbox only; USD only; contracts ≤ 28 days (PayPal's 29-day authorization window); deliverables are JSON/text ≤ 1 MiB.
- The seller is the single PayPal sandbox merchant (no multi-seller marketplace yet).
- Reauthorization is implemented and tested against mocks; live behavior was observed only for the "too soon" case.
- The verifier is evaluated on 30 hand-written cases; small-sample caveats apply. It cannot verify external facts and is untested on non-English content.
- Optional rubric criteria don't block release (see eval case F10); mark criteria `required` when they matter.
- Not escrow; not production-ready. See `docs/spec/security-privacy.md` and `docs/spec/architecture.md` §9 for what would change.
